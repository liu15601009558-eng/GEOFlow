# GEOFlow 稳定性保障方案

> 日期：2026-06-05
> 目标：防止重复推送、图片异常、SEO描述污染等问题再次发生

---

## 一、问题根因分析

| 问题 | 根因 | 影响范围 |
|------|------|---------|
| 重复推送 | sync_article.php 无重复检查，每次POST都INSERT | 所有站点 |
| 图片不显示 | baseUrl 使用了不存在的 img 子域名 | 程恩 |
| SEO描述污染 | Markdown图片语法未被清理就写入 seo_description | 程恩 |
| 文件名空格 | Markdown解析器不支持URL中的空格 | 程恩 |

---

## 三、具体预防措施

### 3.1 GEOFlow端（推送前）

**文件**：`/var/www/html/bin/auto_push_standalone.php`

| 措施 | 实现方式 | 优先级 |
|------|---------|--------|
| 图片URL统一 | baseUrl 使用站点主域名，不用子域名 | P0 |
| 文件名空格处理 | 推送前 URL encode 空格为 %20 | P0 |
| 摘要清洗 | generateCleanSummary 去除所有Markdown语法 | P0 |
| 推送前查重 | 先调 list_titles API 检查标题是否存在 | P1 |
| 推送日志 | 记录每次推送的标题、目标、结果 | P1 |

### 3.2 远端sync_article.php（接收端）

**文件**：各站点 `/sync_article.php`

| 措施 | 实现方式 | 优先级 |
|------|---------|--------|
| INSERT前查重 | SELECT aid WHERE title=? AND is_del=0 | P0 |
| 存在则UPDATE | 已有文章更新内容而非新建 | P0 |
| seo_description清洗 | 写入前去除 ! image /img/ 等残留 | P0 |
| 图片URL校验 | 确保 src 使用正确域名 | P1 |
| 返回action字段 | 响应中区分 insert/updated | P1 |

### 3.3 定时监控（告警）

**方式**：cronjob 每日执行

| 检查项 | 阈值 | 告警方式 |
|--------|------|---------|
| 重复文章数 | > 0 | 立即告警 |
| 异常SEO描述 | > 10 | 立即告警 |
| 错误图片URL | > 0 | 立即告警 |
| 同步接口状态 | HTTP != 200 | 立即告警 |
| 推送失败数 | > 5/天 | 立即告警 |

### 3.4 数据库约束

| 措施 | SQL | 优先级 |
|------|-----|--------|
| 标题唯一索引 | CREATE UNIQUE INDEX idx_title ON ey_archives(title, is_del) | P2 |
| 定期清理任务 | 每周清理 is_del=1 的记录 | P2 |

## 四、执行计划

### 第一阶段：代码加固（1小时）

1. 修改 auto_push_standalone.php
   - 固定 baseUrl 为主域名
   - 添加文件名空格处理
   - 添加推送前查重逻辑

2. 修改所有站点 sync_article.php
   - 添加 INSERT 前重复检查
   - 添加 seo_description 清洗
   - 返回 action 字段

### 第二阶段：监控部署（30分钟）

1. 创建健康检查脚本
2. 配置 cronjob 每日执行
3. 配置告警通知

### 第三阶段：数据库加固（15分钟）

1. 添加唯一索引（可选，需评估性能影响）
2. 配置定期清理任务

## 五、验收标准

| 检查项 | 标准 | 验证命令 |
|--------|------|---------|
| 重复检查 | 新推送同标题文章不重复创建 | 手动推送测试 |
| 图片URL | 所有图片使用主域名 | SQL查询 |
| SEO描述 | 无 ! image /img/ 残留 | SQL查询 |
| 监控告警 | 异常时能收到通知 | 模拟异常测试 |

## 六、回滚方案

每个修改点都有备份：
- sync_article.php.bak
- auto_push_standalone.php.bak

如出现问题，直接恢复备份文件即可。
